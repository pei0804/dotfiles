# 提案パケットの型

修正依頼は「直してほしい」ではなく、相手がそのまま取り込める形で出す。1論点 = 1パケット。

## 型

```
*{論点名}（第◯条{第◯項}）*

現状
{現行の条文を一字一句そのまま引用}

修正案
{修正後の条文の完全形。差分だけでなく全文}

{理由を1〜2文。何を防ぐ・可能にするための変更かを書く}
```

依頼全体の末尾に1回だけ添える。

```
文言は貴社法務のご確認に合わせて調整いただいて構いません。
```

## それぞれの要素がなぜ必要か

**現状の引用。** どの文言を指しているかの認識ズレを消す。版が複数あると「第◯条」だけでは特定できない。

**修正案は完全な条文で。** 「◯◯という趣旨を足してほしい」だと相手方の法務が条文化を持ち帰り、往復が1回増える。そのまま貼れる条文なら取り込みが即日で済む。文体は相手方の文書に合わせる（「ものとする」調、条項参照の書式、全角数字など）。こちらの文体を持ち込むと相手が書き直すことになり、書き直しの過程で意図が変わるリスクがある。

**理由。** 相手方の法務は理由から意図を読み、意図に沿った文言調整を返してくる。理由がないと文言だけが独り歩きし、こちらの目的を外した対案が返ってくる。逆に、相手方から来た対案に理由が付いていたら、文言ではなく理由に対して評価する。

**調整余地の一言。** 文言の細部で往復しないための逃げ道。意図が守られる限り文言は任せる、という姿勢を明示すると相手方の法務が動きやすい。

## 送付時の組み立て

- 複数論点はまとめて1通にする。相手方の社内往復（窓口 → 法務 → 窓口）が1回で済む
- 実質論点と事務項目（表記統一・日付・締結方式）はセクションを分ける。混ぜると事務の指摘が実質論点の議論を薄める
- 冒頭に、既に合意できている点を1〜2文で先に置く。「残っているのはこれだけ」が伝わると相手も締結に向けて動きやすい
- 相手方の対案を受け入れる場合も、無言で流さず「その内容で問題ありません」と明示する。台帳の状態も closed に進める

## 対案が返ってきたときの評価手順

1. 対案の理由を読む。理由がこちらの意図と噛み合っているか
2. 文言がこちらの用途を実際にカバーするか、具体的な利用場面（誰が・いつ・何をする）を当てて読む。目的や範囲の限定が入った場合、その限定の中にこちらの用途が入っているかを確認する
3. 実質が前進していれば受ける。表現が違うだけで意図が守られているなら、文言の好みで往復しない
4. 崩れている場合は、どの一語で崩れるかを特定して、その一語だけ直す再提案にする
