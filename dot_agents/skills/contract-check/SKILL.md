# contract-check: 受領した契約書の検査

相手方から受領した契約文書の版（rev）を検査する。対になる contract-draft（修正案づくり）と、リポジトリに置く交渉台帳を介して連携する。

検査の柱は3つ。**頼んだものが入ったか**（台帳との突合）、**頼んでいないものが混ざっていないか**（前版との diff。正本が相手方にある以上、こちらが把握していない変更は毎版検出する必要がある）、**文書として締結に耐えるか**（機械検査）。

## 秘匿情報の扱い

このスキルには組織固有の事実を書かない。金額の突合先（社内の承認資料）、締結の送付先、過去契約の判断は、作業リポジトリのナレッジ・メモリ・交渉台帳から引く。

## ワークフロー

### 1. 抽出

`scripts/extract_docx.py` を受領ファイルに実行する。本文テキスト、変更履歴の残存件数、コメント一覧、条マップ、表記の注意箇所が出る。

```bash
python3 {このスキルのパス}/scripts/extract_docx.py 受領版.docx --text-out rev_new.txt
```

前版があれば同様にテキスト化し、`diff` で全差分を取る。抽出テキストは変更履歴を反映した状態（挿入は含み、削除は除く）なので、版間 diff がそのまま実質差分になる。

### 2. 条番号ずれの追跡

条マップを前版と並べ、条の挿入・削除で番号がずれていないか確認する。ずれている場合、影響は2箇所に出る。文中の条項参照（「第◯条に定める」が正しい先を指しているか、特に存続条項と準用条項）と、交渉台帳の論点の条番号。台帳側は最新版基準に更新し、旧番号を併記する。

### 3. 台帳との突合（頼んだものが入ったか）

交渉台帳の proposed 状態の論点ごとに、送付した提案パケットの条文と受領版の条文を突き合わせる。判定は3値で報告する。

- **反映**: 提案どおり、または意図を保った文言調整。→ 状態を reflected に
- **対案**: 文言が変えられている。どの一語が変わり、こちらの意図（具体的な利用場面）がまだカバーされるかを評価して報告。→ 状態を countered に。以降の対応は contract-draft へ
- **未反映**: 入っていない。→ proposed のまま、報告で明示

### 4. 依頼外の変更の検出

diff のうち、台帳のどの論点にも対応しない変更をすべて列挙する。無害な表記修正と実質変更を分け、実質変更には条文と影響の評価を付ける。ここを飛ばすと、相手方だけが知っている変更を締結することになる。

### 5. 機械検査

`references/check-procedures.md` の手順で行う。参照整合、金額の検算、表記、定型条項の誤記。

### 6. 締結前チェック（最終版のとき）

締結に進む版では追加で確認する。変更履歴・コメントがゼロ（スクリプトのクリーン判定）、締結日欄の扱い、当事者名・代表者・住所、締結方式（記名押印か電子署名か）と社内の締結手続きに必要な情報。送付先などの組織固有情報はナレッジ・メモリから引いて案内する。

### 7. 報告と台帳更新

報告は「反映された論点 / 対案が来た論点 / 未反映の論点 / 依頼外の変更 / 機械検査の結果 / 締結可否」の順で出す。台帳の状態とボールを更新する。対案の評価と再提案が必要なら contract-draft に引き継ぐ。
