# 帰結ウォーク

条文の有無を見るチェックリストとは別の検査。**この建付けのまま進むと、将来の各場面で何が起きるか**をシナリオで展開する。契約類型や権利帰属のような建付けレベルの論点は、条文の欠落としてではなく、シナリオの答えに詰まる形で現れる。

## やり方

下のシナリオを順に契約に当て、それぞれ「**誰が・何を・誰の金で・どの条項を根拠に**」で答える。答えられない、答えが自分たちの想定と食い違う、条項を根拠にできない、のいずれかに当たった箇所が論点。答えに詰まったら、そこで止めずに連鎖質問（後述）で掘る。

## シナリオ集

| シナリオ | 確認すること |
|---|---|
| 納品・稼働後に不具合が見つかった | 誰が直す義務を負うか。無償か有償か。類型で答えが変わる（準委任なら善管注意義務の範囲での対応義務、請負なら契約不適合責任として無償が原則）。どちらの帰結を取るのか意図的に選んでいるか |
| 契約が終了した翌月に、成果物を直したくなった | 誰が直せるか（権利上・技術上）。直す原資は誰が払うか。相手に依頼するしかない建付けになっていないか |
| 相手が倒産した・権利を第三者に譲渡した・買収された | 成果物の利用は続けられるか。利用許諾は誰に対して主張できるか |
| 支払いが事務ミスで数日遅れた | 何が起きるか（催告なしの業務停止・遅延損害金・解除）。重要イベントの直前に起きたらどうなるか |
| 業務の規模が半分になった・倍になった | どの条項で吸収するか。減額・増額の起点（ベースライン）は定義されているか |
| 情報漏洩・セキュリティ事故が起きた | 誰の何の違反になるか。結果保証の書き方だと、事故の発生自体が相手の契約違反になり、相手はその条項を飲めない。賠償上限はどちらに効くか |
| 途中解除した・された | 金と成果物はそれぞれどう動くか。既払い分の成果物はこちらに残るか。未払い分は相手の担保として機能しているか |
| 相手のキーパーソンが交代した | 業務の水準は何で担保されるか。属人性が高い契約で、体制の定義が契約にあるか |

## 連鎖質問

シナリオで詰まった箇所は、1段で止めずに連鎖で掘る。掘るほど論点の格が上がる（文言の修正 → 条項の追加 → 建付けそのものの見直し）。

権利帰属での実例の型。

1. この成果物は誰の資産か → 相手の資産で、こちらは利用許諾を受けるだけ
2. では誰が保守するのか → 資産の持ち主である相手にやってもらうことになる
3. その原資は誰が払うのか → こちらが払い続けることになる
4. 保守の水準はどう担保するのか → 自己管理と同等の水準を約束させる条項が要る
5. **そこまでするなら、そもそも権利をこちらが持つ建付けの方がよいのではないか** → 建付けの見直しとして提起する

## 相場観との突合

契約の金額と性質（助言か、開発か、成果物が残るか）に対して条項の厚みが釣り合っているかを見る。具体的な手順は、**同種の標準契約（開発委託の基本契約書等）や過去の類似契約を条タイトルのレベルで並べて突合し、欠けている条を列挙する**こと。欠けをすべて足すのではなく、「欠けているのは選択の結果か、見落としか」を1つずつ答えられる状態にする。過去に別性質の契約（作業ベースの準委任等）で許容した判断は、性質が変わった契約ではそのまま流用しない。

## 学習ループ

社内法務や相手方法務から、この文書にない種類の指摘を受けたら、その場の対応で終わらせず**推論を一般化してこの文書かチェックリストに還元する**。書くのは推論の型と法的な帰結（一般知識）だけで、案件固有の事実（社名・金額・判断）は交渉台帳と締結記録の側に残す。
